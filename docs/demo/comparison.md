# Recorded synthetic rule comparison

This demonstration evaluates the same signed **recorded synthetic** inputs
under three rules. It is not a live snapshot and has not been posted.
Counts mean eligible event keys, not issued on-chain records.

After installing the evaluator dependencies, reproduce the report from the
repository root with one command (each run uses a new empty output directory):

```sh
(cd evaluator && node_modules/.bin/tsx src/cli.ts compare --params test/fixtures/comparison/params.json --out "$(mktemp -d /tmp/mizar-comparison.XXXXXX)")
```

The console output and the sole output file, `comparison.md`, contain the same
NON-CANONICAL report below. The command rejects remote sources, RPC settings,
and nonempty output directories. It emits no manifest, Merkle root or claim
proof. `evaluate` and `verify` retain their existing behavior.

The [published dataset](../../evaluator/test/fixtures/comparison/README.md)
is generated by the existing fixture generator with `--comparison`.
Honest attendees meet each other twice. Mallory's three phones meet only each
other; only one phone has a credential representing one World ID. In this
isolated group the full rule yields zero, which is within the pitch's
at-most-one limit. The walk-in has a credential but no encounters. Venue
check-in is assumed for the scenario, not measured by this evaluator.

Synthetic signatures and block mappings test the rule and replay mechanics.
They do not establish live World ID verification, physical presence, real BLE
encounters, or chain anchoring, and do not prevent relay or collusion by
multiple verified humans.

The command above produced this expected output, checked byte-for-byte by
`evaluator/test/compare.test.ts`:
